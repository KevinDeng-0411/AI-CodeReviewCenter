# 团队化升级实施计划:会话按用户隔离

> 本计划是[团队化升级计划](团队化升级计划.md)的执行层落地,具体到文件、函数和测试。
> 范围:认证 + 会话隔离 + 前端登录。**不含**部署上线、guard 升级(advisory lock)。

## 已确认的决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 测试策略 | FastAPI `dependency_overrides` 注入测试用户 | 现有 285 测试无需逐个改;隔离测试走真实认证 |
| Token | 只发 access token,过期 7 天 | 实验室内部工具,省 refresh 轮换逻辑 |
| Guard | 保留进程内 `set[str]`,暂不升级 | 不部署上线=单 worker,内存 guard 正确;advisory lock 等多 worker 再做 |

## 权限模型(不变,复用设计文档)

```text
认证(JWT) -> 你是谁
会话/消息 -> user_id 私有(列表过滤 + 归属校验 404)
知识库/记忆/Prompt/审计记录 -> 全员共享(只加"需登录",不加 user_id 过滤)
角色 -> admin/member 二分(admin 才能建账号、改 Prompt)
```

## 阶段 A:认证基础(后端)

### A1. 新增依赖
- `codeaware-py/pyproject.toml`:加 `passlib[bcrypt]`(密码哈希)+ `python-jose[cryptography]`(JWT 编解码)

### A2. 新增 User model
- 新建 `app/models/user.py`:
  ```python
  class User(Base):
      __tablename__ = "users"
      id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
      username: Mapped[str] = mapped_column(String(50), unique=True, nullable=False)
      password_hash: Mapped[str] = mapped_column(String(255), nullable=False)
      role: Mapped[str] = mapped_column(String(20), nullable=False, server_default="member")  # admin/member
      display_name: Mapped[str | None] = mapped_column(String(100), nullable=True)
      is_active: Mapped[bool] = mapped_column(Boolean, nullable=False, server_default=text("true"))
      created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now(), nullable=False)
      __table_args__ = (Index("ix_users_username", "username"),)
  ```
- `app/models/__init__.py`:导出 `User`

### A3. 配置项
- `app/core/config.py` 加:
  ```python
  jwt_secret_key: str = ""        # 启动时校验非空,空则启动失败(fail-closed)
  jwt_algorithm: str = "HS256"
  jwt_expire_hours: int = 168     # 7 天
  ```
- `codeaware-py/.env.example` + `.env`:加 `JWT_SECRET_KEY=<随机字符串>`

### A4. 安全工具
- 新建 `app/core/security.py`:
  - `hash_password(plain) -> str`(passlib bcrypt)
  - `verify_password(plain, hash) -> bool`
  - `create_access_token(user_id, role) -> str`(jose, 带 `sub`/`role`/`exp`)
  - `decode_token(token) -> dict`(失败抛 `AuthError`)

### A5. 认证依赖
- `app/api/v1/deps.py` 新增:
  - `get_current_user(token=Depends(oauth2_scheme), db=Depends(get_db)) -> User`:从 `Authorization: Bearer` 解析 token -> 查 User -> 校验 `is_active` -> 返回 User;失败抛 401 `AUTH_INVALID_TOKEN`
  - `require_admin(user=Depends(get_current_user)) -> User`:role != admin 抛 403
  - **测试 override 钩子**:fixture 里 `app.dependency_overrides[get_current_user] = lambda: test_user`,285 个老测试零改动

### A6. Auth schema + router
- 新建 `app/schemas/auth.py`:`LoginRequest(username, password)`、`TokenResponse(access_token, token_type, user)`、`UserOut(id, username, role, display_name)`
- 新建 `app/api/v1/auth.py`,前缀 `/api/auth`:
  | 方法 | 路径 | 鉴权 | 说明 |
  |---|---|---|---|
  | POST | `/api/auth/login` | 无 | 校验密码 -> 发 token |
  | POST | `/api/auth/register` | admin | admin 建账号(实验室不开放注册) |
  | GET | `/api/auth/me` | 登录 | 返回当前用户 |
- `app/main.py`:注册 `auth.router`

### A7. 首个 admin 引导
- 新建脚本 `scripts/create_admin.py`:交互式创建首个 admin(username/password/display_name)-> 写 users 表
- 首次部署时跑一次,之后用 `/api/auth/register`(admin 鉴权)建其余账号

### A8. 迁移 0007
- 新建 `alembic/versions/0007_add_users_table.py`(`down_revision="0006"`):建 `users` 表
- **不在此迁移改 conversations/messages**--那是阶段 B 的 0008,保持迁移原子性

### A9. 阶段 A 测试
- 新建 `tests/test_auth.py`:
  - login 成功发 token、密码错 401、用户不存在 401
  - register 非 admin 调 403、admin 成功建号
  - me 带 token 返回用户、不带 token 401、token 过期/伪造 401
  - **现有 285 测试加 fixture override,确认仍全绿**

## 阶段 B:会话隔离(后端)

### B1. 迁移 0008
- 新建 `alembic/versions/0008_add_user_id_to_conversations.py`:
  - `ALTER TABLE conversations ADD COLUMN user_id BIGINT REFERENCES users(id)`
  - `ALTER TABLE messages ADD COLUMN user_id BIGINT REFERENCES users(id)`
  - **回填**:把所有存量 conversations/messages 的 user_id 设为引导创建的默认 admin id(从 users 表查 role=admin 的第一条;没有则报错中断,提示先跑 create_admin)
  - 加 `NOT NULL` 约束(回填后)+ 索引 `ix_conversations_user_id`
  - downgrade 对称回退(先 drop constraint/index 再 drop column)

### B2. Model 加字段
- `app/models/conversation.py`:+ `user_id` + `user` relationship
- `app/models/message.py`:+ `user_id`(冗余,加速查询;文档已说明)

### B3. Chat 路由加鉴权 + 隔离
- `app/api/v1/chat.py` 所有 5 个路由加 `user: User = Depends(get_current_user)`:
  - `list_conversations`:`ChatService.list_conversations(user.id)` -> 只返回当前用户的
  - `get_conversation` / `delete_conversation`:归属校验 -- 不是当前用户的 cid 返回 **404**(不暴露"存在但无权")
  - `send` / `send_stream`:把 `user.id` 传给 `coordinator.prepare_turn(...)`

### B4. TurnCoordinator 接受 user_id
- `app/ai/services/turn_coordinator.py` 的 `prepare_turn(cid, message, user_id)`:
  - 新会话(cid=None):创建时写入 `user_id`
  - 已有会话:校验 `conversation.user_id == user_id`,不匹配抛 `ChatConversationNotFound`(复用 404,不泄露)
- `ChatService.list_conversations(user_id)`:`WHERE user_id = :uid ORDER BY id DESC`

### B5. 共享资源路由只加"需登录"
- `knowledge.py` / `memory.py` / `prompt.py` / `code_review.py` / `unit_test.py` / `ai_readme.py`:每个路由加 `Depends(get_current_user)`(确保登录),**不加** user_id 过滤(全员共享)
- `prompt.py` 的写操作(create/activate)改用 `Depends(require_admin)`

### B6. 阶段 B 测试
- 新建 `tests/test_chat_isolation.py`:
  - 建两个真实用户 alice/bob(不走 override,走真实 token)
  - alice 建会话 -> bob 的列表看不到
  - bob 用 alice 的 cid 调 send/get/delete -> 全 404
  - alice 上传知识库 -> bob 搜索能命中(共享验证)
  - 未登录访问任意路由 -> 401
- **关掉 override fixture 跑一遍**,确认真实鉴权链路通

## 不做(及理由)

| 不做 | 理由 |
|---|---|
| PG advisory lock | 不部署=单 worker,内存 guard 正确;多 worker 部署时再做 |
| refresh token | 实验室内部,access 7 天 + 重登足够 |
| 用户管理 UI | 阶段 C 只做登录+退出;admin 建号用 create_admin 脚本或 register API,UI 后续按需加 |
| OAuth/SSO | 内部工具不需要 |
| 改 285 老测试 | dependency_overrides 注入测试用户,零改动 |

## 验收(对齐设计文档 §5)

1. `create_admin` 建首个 admin -> `register` 建 alice/bob
2. alice 登录上传"团队编码规范"
3. bob 登录在 Chat 问"编码规范" -> 命中 alice 的文档(共享✓)
4. alice/bob 各自建对话,互不可见(隔离✓)
5. bob 用 alice 的 cid -> 404(归属✓)
6. 未登录访问 -> 401(鉴权✓)
7. 后端 285 老测试 + 新 auth/隔离测试全绿
8. 前端 36 老测试 + 新 auth 测试全绿
