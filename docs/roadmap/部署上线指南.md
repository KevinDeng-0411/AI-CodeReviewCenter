# CodeAware 部署上线指南

> **场景 A**：实验室局域网部署（默认,§1-§3.6,§4-§6）。一台 Linux/Mac 服务器,团队成员通过局域网访问。
> **场景 B**：云服务器部署（扩展,§3.7）。火山引擎/阿里云/腾讯云 ECS,公网访问 + HTTPS。
> 目标：最小运维负担,≤3 小时从零到上线。

---

## 1. 部署架构

```text
                    实验室局域网
                         │
                 http://<server-ip>:8000
                         │
              ┌──────────┴──────────┐
              │    FastAPI :8000     │  ← Python 后端 + 前端静态文件
              │  (systemd 守护)      │
              └──────────┬──────────┘
                         │
          ┌──────────────┼──────────────┐
          │              │              │
   PostgreSQL :5433   Redis :6380   Ollama :11434
   (docker-compose)  (docker-compose) (docker-compose)
          │                             │
     pgvector + BM25              bge-m3 embedding
```

**说明**：
- 前端 `npm run build` 产物（`dist/`）由 FastAPI 静态托管,不单独部署 Nginx
- PG/Redis/Ollama 用 docker compose 管理,数据卷持久化
- Python 后端用 systemd 守护,方便更新代码（`git pull` + `systemctl restart`）
- DeepSeek API 走公网,不经过本机

> **为什么后端不用 Docker？** 实验室场景下代码迭代频繁（改 bug、加功能），systemd 方式只需 `git pull` + 重启,不用每次重新 build 镜像。PG/Redis/Ollama 用 Docker 是因为它们几乎不需要更新。

---

## 2. 服务器要求

| 项 | 最低 | 推荐 |
|---|---|---|
| OS | Ubuntu 22.04+ / macOS 13+ | Ubuntu 24.04 LTS |
| CPU | 4 核 | 8 核（Ollama embedding 吃 CPU） |
| 内存 | 8 GB | 16 GB（Ollama bge-m3 ~2GB + PG buffer） |
| 磁盘 | 30 GB | 50 GB+（docker 镜像 + 知识库文件 + DB 数据） |
| 网络 | 局域网静态 IP | 同 |

> **最低配 8GB 建议**：bge-m3 模型约 2GB,Ollama 运行时约 2-3GB,PG + Redis 约 1GB,后端约 500MB。

## 3. 部署步骤

### 3.1 服务器初始化

```bash
# 安装基础依赖（Ubuntu）
sudo apt update && sudo apt install -y git python3.12 python3.12-venv curl

# 安装 Docker
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
# 重新登录使 docker 权限生效

# 安装 uv（Python 包管理）
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.cargo/env

# 安装 Node.js（前端构建用，LTS 版本）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

### 3.2 拉取代码

```bash
git clone <your-github-repo-url> /opt/codeaware
cd /opt/codeaware
```

### 3.3 启动基础服务（PG + Redis + Ollama）

```bash
# 拉取 bge-m3 模型（首次需要下载 ~2GB）
docker compose up -d ollama
docker exec ai-center-ollama ollama pull bge-m3

# 启动全部基础服务
docker compose up -d
# 等待 healthy: docker compose ps
```

### 3.4 部署后端

```bash
cd /opt/codeaware/codeaware-py

# 安装 Python 依赖
uv sync --frozen

# 配置环境变量
cp .env.example .env
# 编辑 .env：
#   LLM_API_KEY=sk-your-real-key
#   PG_HOST=localhost  (保持，docker 端口映射到 5433)
#   REDIS_HOST=localhost
#   OLLAMA_BASE_URL=http://localhost:11434
#   PG_DB=ai_center_py

# 运行数据库迁移
uv run alembic upgrade head

# 构建前端（生产构建，产物在 frontend/dist/）
cd frontend && npm ci && npm run build && cd ..
```

### 3.5 配置 systemd 守护

```bash
sudo tee /etc/systemd/system/codeaware.service << 'EOF'
[Unit]
Description=CodeAware Backend
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=codeaware
WorkingDirectory=/opt/codeaware/codeaware-py
Environment="PATH=/opt/codeaware/codeaware-py/.venv/bin:/usr/local/bin:/usr/bin:/bin"
ExecStart=/opt/codeaware/codeaware-py/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 创建专用用户
sudo useradd -r -s /bin/false codeaware
sudo chown -R codeaware:codeaware /opt/codeaware

# 启动
sudo systemctl daemon-reload
sudo systemctl enable codeaware
sudo systemctl start codeaware

# 验证
sudo systemctl status codeaware
curl http://localhost:8000/api/ai/health
```

> **为什么 `--workers 2`？** 实验室 5-20 人并发很低,2 个 worker 足够。更多 worker 意味着每个 worker 加载一份 Ollama embedding 的内存,反而浪费。

### 3.6 配置防火墙（如果需要局域网访问）

```bash
# Ubuntu ufw
sudo ufw allow from 192.168.0.0/16 to any port 8000
# 或只开放给实验室网段

# Mac 在"系统设置 → 防火墙"中允许 Python
```

## 3.7（可选）云服务器部署——以火山引擎为例

如果实验室没有固定机器,或需要校外访问,用云服务器。步骤和本地部署 90% 相同,差异只在网络层。

### 3.7.1 服务器选购

| 配置项 | 最低 | 推荐 | 理由 |
|---|---|---|---|
| 规格 | 4C8G | 8C16G | Ollama bge-m3 嵌入吃 CPU,8G 勉强跑 |
| 系统盘 | 40 GB | 60 GB | Docker 镜像 + 模型 (~2GB) + DB 数据 |
| 镜像 | Ubuntu 22.04/24.04 | 同 | 文档命令基于 Ubuntu |
| 网络 | 按量带宽 5 Mbps | 按量 10 Mbps | 嵌入和 LLM 调用不上行,主要是下行 |
| 地区 | 离实验室最近的 region | 同 | 降低延迟 |

> **成本预估（2026 年火山引擎参考价）**：4C8G + 40GB 云盘 + 5Mbps ≈ **¥200-300/月**。8C16G ≈ **¥350-500/月**。
> 不需要 GPU 实例（bge-m3 纯 CPU 嵌入,DeepSeek 走 API）,GPU 实例 ¥5-20/小时,不值得。
>
> **首次购买建议**：买 1 个月 4C8G,试跑一周确认性能够用,不够再升配或改成包年（约 7 折）。

### 3.7.2 安全组配置

火山引擎控制台 → ECS → 安全组 → 添加入方向规则：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 实验室出口 IP | SSH 管理（**不要 0.0.0.0/0**） |
| 80 | 0.0.0.0/0 | HTTP → 自动跳转 HTTPS |
| 443 | 0.0.0.0/0 | HTTPS（Caddy 自动签发 Let's Encrypt） |
| 8000 | **不要对外开** | 后端只监听 localhost,由 Caddy 反代 |

> **关键**：后端 `--host 127.0.0.1`,不直接暴露到公网。所有流量走 Caddy 反代,HTTPS 加密。

### 3.7.3 加一层 Caddy（反代 + 自动 HTTPS）

局域网部署不需要这步,但**公网部署必须加**——HTTP 明文过公网会泄露 JWT token。

```bash
sudo apt install -y caddy

sudo tee /etc/caddy/Caddyfile << 'EOF'
# 你的域名（如果没有域名用 IP 也行，但 HTTPS 只能用域名签）
codeaware.example.com {
    reverse_proxy 127.0.0.1:8000
}

# 如果没有域名，用 IP + HTTP（临时方案）：
# :80 {
#     reverse_proxy 127.0.0.1:8000
# }
EOF

sudo systemctl enable caddy
sudo systemctl restart caddy
```

Caddy **自动申请和续期** Let's Encrypt 证书,零配置。如果没有域名,用 nip.io 免费通配符域名（`codeaware.你的IP.nip.io`→ Let's Encrypt 也能签）。

### 3.7.4 修改 systemd 监听地址

云服务器上 uvicorn 只监听 127.0.0.1,不对外：

```bash
# systemd service 的 ExecStart 改为：
ExecStart=.../uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2
```

### 3.7.5 Ollama embedding 的云端选择

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A: 自建 Ollama**（推荐） | 嵌入免费,内网延迟零 | 吃 CPU,4C 规格嵌入一次约 0.3-0.5 秒 |
| B: 火山方舟 embedding API | 不占本机 CPU,响应快 | 按 token 计费,长期成本高于自建 |
| C: 混用 | 自建为主,高峰时切 API | 需要做 fallback 逻辑 |

> **建议**：先方案 A 跑起来——bge-m3 嵌入是**一次性的**（上传文档时跑一次,查询时跑一次,不是高频操作）,4C CPU 完全够。如果后续并发查询多到 CPU 瓶颈,再加方案 B 做 auto-fallback。

### 3.7.6 与局域网部署的差异总结

| | 局域网 | 云服务器 |
|---|---|---|
| 网络 | 内网 HTTP,直接访问 | 公网 HTTPS,Caddy 反代 |
| 防火墙 | ufw 或 Mac 防火墙 | 安全组（云控制台） |
| 域名 | 不需要 | 建议有（或 nip.io） |
| 成本 | 电费 + 机器 | ¥200-500/月 |
| 可用性 | 机器关了就用不了 | 99.95% SLA |
| 运维 | 自己修机器 | 云厂商负责硬件 |

## 4. 日常运维

```bash
# 更新代码
cd /opt/codeaware && git pull
cd codeaware-py && uv sync --frozen
cd frontend && npm ci && npm run build && cd ..
sudo systemctl restart codeaware

# 查看日志
sudo journalctl -u codeaware -f

# 重启基础服务
cd /opt/codeaware && docker compose restart

# 备份数据库
docker exec ai-center-postgres pg_dump -U aicenter ai_center_py > backup_$(date +%Y%m%d).sql

# 查看服务状态
sudo systemctl status codeaware
docker compose ps
curl http://localhost:8000/api/ai/health
```

## 5. 监控建议

先用最简单的方案,出了问题再加：

| 层级 | 方案 | 何时加 |
|---|---|---|
| 进程存活 | systemd `Restart=always` | 部署时就有 |
| 日志 | `journalctl -u codeaware` | 部署时就有 |
| 磁盘 | `df -h` 定期检查（Ollama 模型 + DB 增长） | 部署时就有 |
| API 健康 | `curl /api/ai/health` 定时任务 | 第二周 |
| DB 连接池 | 后端日志加 SQLAlchemy pool 指标 | 出现超时时 |
| APM | 不加。实验室 20 人不需要 OpenTelemetry | 除非出现性能问题 |

## 6. 不做的事（及为什么）

| 不做 | 适用场景 | 理由 |
|---|---|---|
| Docker 化后端 | 都适用 | 代码更新频繁（git pull + restart < 重新 build 镜像） |
| Nginx（局域网） | 局域网 | FastAPI 已静态托管前端,单进程够用 |
| Nginx（云服务器） | 云服务器 | 用 Caddy 替代——自动 HTTPS + 配置更简单 |
| K8s / Docker Swarm | 都适用 | 单机部署不需要编排 |
| HTTPS / 域名（局域网） | 局域网 | 内网使用 HTTP 即可 |
| CI/CD 自动部署 | 都适用 | 20 人团队手动 git pull 完全可控 |
| 监控面板/Grafana | 都适用 | 出了性能问题再加,不提前投入 |
| GPU 实例 | 云服务器 | bge-m3 CPU 嵌入够用,GPU 实例 ¥5-20/小时不值得 |
| 独立 embedding 服务 | 都适用 | Ollama 本地嵌入够用,省云端 API 费 |
