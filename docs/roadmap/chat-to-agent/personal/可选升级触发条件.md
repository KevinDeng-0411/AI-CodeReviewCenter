# 个人路线之外的可选升级触发条件

> 本文件只定义“什么时候值得重新评审”，不构成实施卡或预授权。

默认路线在 S5 结束。以下能力没有真实问题和基线指标时保持关闭：

| 能力 | 只有出现这些证据才重新评审 | 重新评审时必须补充 |
|---|---|---|
| S3 / LangGraph | 固定分支编排明显增多；需要节点级 trace；简单循环已难测试 | 新 ADR、与当前 S4/S5 兼容的迁移卡；旧 S3 文档不能直接执行 |
| S6 / Durable Run | 任务超过 HTTP 生命周期；频繁断线；确需取消、重试、后台索引或重启恢复 | 任务时长/失败数据、Run/幂等模型、队列运维成本 |
| S7 / Sandbox Patch | 用户确实需要让模型生成并运行补丁 | immutable materializer、rootless runner、独立权威测试套件 |
| S8 / Local Action | 手工应用已验证补丁和提交成为持续瓶颈 | S7 evidence、精确 ActionManifest、审批与 Git CAS |
| S9-A 外部写 | 确需自动 push/draft PR | S8；若服务远程/多人还必须先完成身份阶段 |
| S9-B MCP | 原生 adapter 数量和维护成本已有量化问题 | 固定协议版本、R0 映射、连接器安全测试；只读 MCP 可从 S5 评审 |
| S9-C 远程身份 | 首次计划非 loopback、多人或多租户部署 | OIDC、membership、tenant isolation 和新的威胁模型 |
| S9-D 多 Agent | 单 Agent held-out eval 证明上下文/工具过载或并行收益 | S6 evidence、预注册对照评测；写任务再补 S7/S8 |

规则：

- 可选能力不出现在默认 completion 清单中，也不创建 `skipped/passed` 假 manifest。
- 触发后先修改路线、依赖 DAG、阶段卡和证据 schema，再请求该能力的实施授权。
- S3 只能在 S4 前按旧“确定性 Chat Graph”设计评审；S4/S5 已完成后若再引入 Graph，
  必须重新设计为兼容当前工具循环的迁移阶段。
- 远程身份完成不自动开启写能力；写能力仍需自己的证据和授权。
