# S1-lite：精简项目隔离

> **状态：Future / Locked。路线档案：`personal-local-readonly`。**
>
> 只有 C1/C2/C3/C4 manifests 通过且用户在其后明确授权 S1，才能实施。

## 1. 达成的功能

用户可以创建并切换本地 Project。切换后，Conversation、Knowledge、Memory、
Code Review/Unit Test 记录和 AIReadMe 只展示、检索和修改当前项目的数据。

## 2. 最小实施范围

- 新增 `projects`，创建确定性的默认 `Local` Project。
- 给以下父实体增加非空 `project_id`：
  - `conversations`
  - `documents`
  - `long_term_memories`
  - `ai_operation_records`
  - `ai_readme_documents`
- `messages` 通过 Conversation、`knowledge_chunks` 通过 Document 继承作用域，不冗余复制。
- 历史数据全部回填到默认 Project，并建立 FK/必要索引。
- 提供不可变 `ProjectScope(actor_id, project_id)`：
  - actor 由服务端固定为 `local-single-user`；
  - project 只从 `X-Project-ID` 解析；
  - body/query/tool 参数不能成为第二个 project 真相源。
- 所有 JSON、SSE、multipart 请求由前端中央 client 统一注入 project header。
- 提供 `GET/POST /api/projects` 和全局 Project selector；不建设完整管理后台。
- 向量、关键词两条检索腿都必须在 top-k/排序前应用相同 `project_id` 谓词。

## 3. 不做事项

- 不做登录、用户、组织、成员、角色或 RBAC。
- 不开放远程访问，不监听 `0.0.0.0`。
- 不做 Project 删除、合并、成员迁移等管理能力。
- 不接 Git 仓库，不开放 Tool，不引入 LangGraph。
- 不调整 RAG 排名、Prompt、模型或 C1 SSE 语义。

## 4. 自动测试

必须覆盖：

- fresh DB 和已有数据升级后五个 `project_id` 均非空。
- A/B Project 分别写入同关键词 Knowledge、Memory、Conversation 后互不召回。
- B header 读取/删除 A 的 ID/cid 返回统一 not-found，A 数据与 Redis 不变。
- CR/UT/AIReadMe list/detail/生成结果均按 Project 隔离。
- JSON、SSE、multipart 都使用同一 header。
- 请求伪造 actor 或 body 中的 project 不会覆盖服务端 scope。
- remote/broad-bind 配置 fail closed。

## 5. 可复制演示

```text
创建 Project A/B
→ A/B 分别写入带唯一 marker 的 Knowledge、Memory 和 Conversation
→ 前端切换 Project
→ 搜索、会话列表和记录只显示当前 Project
→ 使用 B header 请求 A 资源
→ 返回 not-found，A 数据仍存在
```

## 6. 阶段完成条件

- `migration-scope`
- `api-scope`
- `retrieval-isolation`
- `frontend-scope`
- `rollback`

以上 check 全部被 `evidence/S1/manifest.json` 引用并由 validator 通过。回退只在一次性
数据库演练；真实多项目数据不得直接 downgrade。
