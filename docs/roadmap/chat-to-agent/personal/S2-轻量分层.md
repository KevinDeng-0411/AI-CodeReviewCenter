# S2-lite：Agent 必需的轻量分层

> **状态：Future / Locked。路线档案：`personal-local-readonly`。**
>
> 只有 S1 manifest 通过且用户在其后明确授权 S2，才能实施。

## 1. 达成的功能

用户看到的 Chat 行为保持不变，但内部已形成可替换的 ReplyEngine 和只读 application
ports。S4 可以增加 AgentReplyEngine，而不复制消息落库、摘要、缓存和 SSE 流程。

## 2. 最小实施范围

只提取 Agent 真正需要的边界：

- 保留 C1 唯一 `TurnCoordinator`。
- 定义最小稳定类型：
  - `ChatCommand`
  - `ChatContext`
  - `ChatWarning`
  - `ReplyResult`
  - `Citation`
- 提取：
  - `ChatContextBuilder`
  - `ReplyEngine` / `PlainChatReplyEngine`
  - `PostTurnProcessor`
  - `KnowledgeReadPort`
  - `MemoryReadPort`
  - `ChatUnitOfWorkFactory`
- Router 只调用 application use case，不持有 ORM、Redis 或模型 client。
- Tool 将来只能调用 scope 强制存在的 read port，不得直接 SQL。
- transaction A、transaction B 和 post-turn 分别使用短 UoW；等待 LLM 时不持有事务。
- Redis 只在对应 PG commit 后更新。

## 3. 不做事项

- 不引入 LangGraph、双 runtime、checkpoint 或节点 trace。
- 不做全领域 repository/CQRS/事件溯源重构。
- 不新增公共功能、数据库表或 UI。
- 不为架构“纯度”重写 Code Review、Unit Test、AIReadMe 等薄工具。

## 4. 自动测试

必须覆盖：

- 同一 fake model/RAG/Memory fixture 在重构前后得到相同 Prompt、SSE、Message 和 summary。
- ASSISTANT 只保存一次，TurnCoordinator 没有第二份实现。
- PG commit 前 Redis 调用次数为 0。
- context 降级发 `context.warning`；post-turn/cache 降级发 `post_turn.warning`。
- summary watermark/CAS 行为不回归。
- application DTO/state 中不存在 ORM、session、Redis 或模型 client。
- import/architecture test 阻止 router/tool handler 直接访问基础设施实现。

## 5. 可复制演示

```text
固定输入 + fake model + 固定 Knowledge/Memory
→ 在 validated S1 head 记录基线输出与 DB/Redis 结果，并引用 C3 契约
→ 切换到 S2 分层实现
→ 比较规范化 SSE、Message、summary、warning 和缓存
→ 结果行为等价
```
