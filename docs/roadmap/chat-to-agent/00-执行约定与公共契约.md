# Chat → Agent 公共契约

> **状态：Future / Locked。** 本文件保存 Agent 能力的公共语义和安全边界，不授权当前实施。
> 个人项目默认只使用 S1/S2/S4/S5 所需的 Project、Tool、Citation、ChatEvent 子集；
> AgentRun/State/Artifact/Approval 等内容是条件型平台参考，不属于默认 DoD。
> 当前版本先执行[current-release C1–C3](../current-release/README.md)。
>
> 获得用户后续明确授权后，实施模型仍不得在单个 Agent 阶段内自行发明冲突的 State、事件、工具或审批格式。

---

## 0. 未来路线的部署与信任边界

个人默认 S1/S2/S4/S5 只支持 **local single-user** 模式；未来若重新启用高级平台卡，
在独立身份阶段完成前也必须保持相同边界：

```text
actor_id = "local-single-user"  # 服务端常量，不接受 header/body/tool 参数覆盖
REMOTE_ACCESS_ENABLED = false   # personal-local-readonly 中不得开启
bind host = 127.0.0.1 / ::1     # 不允许 0.0.0.0、远程反向代理或公网暴露
```

固定规则：

- `X-Project-ID` 只是本地单用户在多个 Project 数据集之间选择隔离范围；知道 UUID 不等于获得授权，它不是认证凭据。
- `actor_id` 由服务端注入固定 sentinel。默认路线中的 actor/scope 只表示本地静态策略和审计归属，不表示真实用户身份。
- CORS、不可预测 UUID、allowed roots 和 feature flag 都不是认证机制。
- 本地仓库注册等宿主级配置只能由本机 admin CLI 完成，不能把绝对路径作为普通 HTTP 请求输入。
- 条件型 S8 的审批者仍只是当前本地操作者；它不构成多人审批或权限系统。
- 任何远程访问、多人协作或外部身份接入都必须先新增独立 Identity/ProjectMembership 阶段、ADR、威胁模型和迁移，并再次取得用户明确授权；不得通过把 `REMOTE_ACCESS_ENABLED` 改为 `true` 绕过路线门禁。

以上全是 C3 完成并获得后续授权后的未来增量。不得为建立 sentinel actor 或 Project 隔离而改写、复制或提前实施 C1–C3 已冻结的 Chat/SSE/AIReadMe 行为。

### 0.1 未来阶段统一执行与证据规则

所有已获授权阶段的实现、测试、演示、证据和回退必须遵循同一条 fail-closed 执行链：

- 先记录 C3 freeze 和当前卡全部直接依赖 manifests 中的 base commit，再从选定 commit 建立
  **detached 临时 Git worktree**；实现和验收不得改写用户当前工作树。
- shell 示例均从仓库根开始；进入子目录只使用单条命令中的 `(cd codeaware-py && ...)` 或 `(cd codeaware-py/frontend && ...)`，不能依赖上一段留下的当前目录。
- 所有后端、migration roundtrip、integration、live-eval 和故障注入测试都必须通过 `codeaware-py/scripts/run_tests_safe.py`。它必须创建、校验并按精确 identity 清理本次一次性 PostgreSQL/Redis（以及阶段需要的 queue/fixture repo）；禁止裸跑 `pytest`、裸跑 destructive Alembic 或复用开发/共享数据。
- 每阶段唯一机器证据入口是 `docs/roadmap/chat-to-agent/evidence/Sx/manifest.json`。可附
  `report.md` 和哈希引用产物，但旧式文件、Markdown 勾选或未被 manifest 引用的文件
  均不能解锁能力 DAG 中的后继卡。
- 阶段完成必须从仓库根运行 `(cd codeaware-py && uv run python scripts/validate_stage_evidence.py Sx)`，且 validator 校验 commit 祖先、必需 check ID、产物 hash、一次性环境 identity 和精确 cleanup report。
- 功能回退优先关闭 feature flag、切回旧 Prompt/index/runtime。代码与 schema 回退演练只能在另一个 detached 临时 worktree 和另一套一次性 PG/Redis 中完成；禁止在用户当前工作树直接 `git revert`、`checkout/reset/clean` 或执行 Alembic downgrade，禁止对开发/共享/生产库为取证而 downgrade。

任一 target guard、stack identity、cleanup 或 evidence validator 失败，当前阶段保持未完成。

## 1. 生命周期必须分离

`personal-local-readonly` 只落地 Conversation/Message/Memory、S4/S5 请求生命周期内的
ToolResult，以及随 ASSISTANT Message 长期保存的 Citation snapshot；**不创建**
AgentRun、AgentState、持久 ToolCall、RunEvent、Artifact 或 Approval。下表从 AgentRun
开始的六类仅在对应条件型路线重新获批后使用，不能因公共契约已写好而提前建表。

| 对象 | 作用 | 生命周期 | 真相源 |
|---|---|---|---|
| Conversation / Message | 用户对话和展示历史 | 长期 | PostgreSQL |
| Citation snapshot | 回答实际引用的已验证来源 | 跟随 ASSISTANT Message | PostgreSQL `messages.citations_json` |
| Short-term Memory | 最近消息窗口和摘要缓存 | 会话级 | PG 真相 + Redis 缓存 |
| Long-term Memory | 经来源约束的项目/用户事实 | 长期 | PostgreSQL + pgvector |
| AgentRun | 一次 Agent 任务 | 任务级 | PostgreSQL |
| AgentState | Run 内可序列化执行状态 | 节点间 | LangGraph checkpoint |
| ToolCall | 一次工具请求及结果 | Step 级 | PostgreSQL |
| RunEvent | 客户端可重放事件 | Run 级 | PG 真相 + Redis 实时分发 |
| Artifact | 引用、报告、补丁、测试证据 | Run 产物 | PostgreSQL 元数据 + 文件/对象存储 |
| Approval | 对精确副作用的决定 | Run/Step 级 | PostgreSQL |

禁止：

- 把 ORM 实例、session、Redis client、模型 client 放入 `AgentState`。
- 用 Conversation 消息代替 checkpoint。
- 用 checkpoint 代替业务持久化。
- Run 重试时重复保存消息、记忆、工具副作用或补丁。

## 2. 稳定领域类型

以下为语义契约，具体 Pydantic 字段可按阶段逐步落地，但字段含义不得改变。

### 2.1 AgentRunRequest（条件型平台参考，默认路线不实现）

这是 application 层命令的语义结构，不等同于原样 HTTP JSON body。HTTP router 必须组装：

- `project_id` 来自 S1 定义的 `X-Project-ID`/ProjectContext；
- `idempotency_key` 来自 `Idempotency-Key` header；
- `actor_id` 来自服务端固定的 `"local-single-user"` sentinel；
- JSON body 只提供 task、mode、conversation/repository/base commit 和可下调预算。

公共 HTTP body 不再重复 `project_id` 或 `idempotency_key`。若 C3 冻结的兼容 body 暂时仍有这些字段，只能在一个明确删除阶段内接受，且必须与 header 完全一致，否则拒绝。

```python
class AgentRunRequest(BaseModel):
    actor_id: Literal["local-single-user"]
    project_id: UUID
    conversation_id: str | None = None
    repository_id: UUID | None = None
    base_commit: str | None = None
    task: str
    mode: Literal["chat", "agent", "patch"] = "agent"
    idempotency_key: str
    max_model_turns: int = 4
    max_tool_calls: int = 6
    timeout_seconds: int = 300
```

规则：

- `project_id` 从 S1 起强制存在。
- `patch` 模式从 S7 起可用。
- 服务端必须设置硬上限；客户端传入更大值不能突破服务端配置。
- 同一 `idempotency_key + actor_id + project_id` 只能创建一个逻辑 Run。

### 2.2 AgentState

```python
class AgentState(TypedDict, total=False):
    run_id: str
    actor_id: str
    project_id: str
    conversation_id: str
    repository_id: str | None
    repository_snapshot_id: str | None
    base_commit: str | None
    index_version: str | None
    user_message: str
    messages: list[dict]
    context_refs: list[str]
    citations: list[dict]
    tool_calls_used: int
    model_turns_used: int
    pending_approval_id: str | None
    artifact_ids: list[str]
    final_answer: str | None
    error: dict | None
```

State 保存 ID 和 JSON 数据，不保存大型全文、ORM 对象或连接。大型工具结果写 Artifact，只把引用放入 State。

### 2.3 Citation

```python
class Citation(BaseModel):
    citation_id: str
    project_id: UUID
    repository_id: UUID | None = None
    repository_snapshot_id: UUID | None = None
    commit_sha: str | None = None
    index_version: str | None = None
    document_id: int | None = None
    chunk_id: int | None = None
    path: str | None = None
    symbol: str | None = None
    start_line: int | None = None
    end_line: int | None = None
    excerpt: str
    score: float | None = None
```

最终回答只能引用本次 ToolResult 返回的 `citation_id`，不能由模型自行编造文件或行号。
S4 的普通 Knowledge Citation 必须同时包含 `document_id` 和 `chunk_id`，并将 repository
provenance 留空。S5 的 `search_code` 可引用持久 Chunk；`read_file_lines` 可以引用同一
Document 内不与单个 Chunk 重合的任意受限行窗口，此时 `document_id` 必填而 `chunk_id`
允许为空。所有 S5 代码 Citation 都必须固定 `repository_id`、`repository_snapshot_id`、
`commit_sha`、`index_version`、`path`、`start_line` 和 `end_line`，且 excerpt 能从该
immutable Git blob 精确复算。

class Artifact(BaseModel):

## 3. Tool 契约

```python
class ToolDefinition(BaseModel):
    name: str
    version: str
    description: str
    input_schema: dict
    output_schema: dict
    risk: Literal["R0_READ", "R1_SANDBOX", "R2_LOCAL_WRITE", "R3_EXTERNAL_WRITE"]
    required_scopes: list[str]
    timeout_seconds: int
    idempotent: bool
    max_output_bytes: int
```

```python
class ToolResult(BaseModel):
    # 模型/provider 协议返回的不透明 ID；必须原样回传，不能假设为 UUID。
    tool_call_id: str
    # S6 起由应用生成并持久化，跨 Worker attempt/checkpoint 保持稳定。
    logical_tool_call_id: UUID | None = None
    ok: bool
    data: dict | None = None
    citations: list[Citation] = Field(default_factory=list)
    artifact_ids: list[UUID] = Field(default_factory=list)
    error: ToolError | None = None
```

`tool_call_id` 与 `logical_tool_call_id` 是两个命名空间：

- `tool_call_id` 是单次模型响应中的 provider 原始关联 ID，只用于按 provider 协议把 Tool 消息原样关联回去；它是不透明字符串，不能作为数据库主键、幂等键或跨恢复边界的稳定身份。
- `logical_tool_call_id` 是 CodeAware 的内部 UUID。S4/S5 可只在当前进程内生成，S6 起必须在首次执行 Tool 前持久化，并在 Worker 重投递、checkpoint 恢复和 attempt 变化时复用。
- S6 的 ToolCall aggregate 同时保存二者及显式映射记录；provider 重新生成了新的原始 ID 时，不得因此创建第二个逻辑调用。反过来，同一 provider ID 也不能覆盖 fingerprint 不同的逻辑调用。

### 风险等级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| R0_READ | 搜索知识、读取文件、查符号 | 本地静态策略允许且项目隔离校验后自动执行 |
| R1_SANDBOX | 在 immutable source snapshot 的任务专用 overlay 中应用 patch、运行测试 | 独立受限 runner 和预算内自动执行 |
| R2_LOCAL_WRITE | 创建本地分支、提交补丁 | 必须人工审批 |
| R3_EXTERNAL_WRITE | push、创建 PR、评论、合并、发送消息 | S9 前禁用；启用后逐次审批 |

R1 运行时必须遵循 S7 的安全物化契约：普通 API/Worker 不得对不可信候选源码执行 `git worktree add/checkout`。本文其他位置提到的 detached 临时 worktree 只用于实施代码隔离或在一次性数据栈中验证版本回退，不是 Agent patch 的运行时沙箱。

所有 Tool handler 必须：

- 通过 service/port 访问领域能力，不直接拼 SQL；
- 校验 `project_id` 和本地静态 scope；不得把校验描述成用户授权；
- 设置 timeout、输出大小和错误类型；
- 对副作用使用幂等键；
- 将外部内容视为不可信数据；
- 产出结构化结果，不把自然语言工具输出直接当系统指令。

## 4. SSE / RunEvent 契约

当前版本 C1 已停止使用裸 token 行和单一 `[DONE]` 推断状态。S1–S5 必须直接扩展 C1 冻结的 `ChatEventBase`，不能用 `request_id`、`run_id` 或阶段私有 envelope 替换它：

```python
class ChatEventBase(BaseModel):
    protocol_version: Literal[1]
    conversation_id: str
    turn_id: str
    sequence: int
```

事件类型只由 SSE `event:` 行承载，不在 JSON 内再放一份可漂移的 event name。所有 Chat、Tool 和 Citation 事件都继承这四个字段。`turn_id` 是 C1 当前 Chat turn 的 correlation ID，不是 AgentRun；`sequence` 从本 stream 的 1 开始严格递增，SSE `id` 必须等于十进制 `sequence`：

```text
id: 12
event: token.delta
data: {"protocol_version":1,"conversation_id":"...","turn_id":"...","sequence":12,"delta":" hello"}

```

`data` 必须是单行 JSON；前端只解析 JSON，不对 `delta` 调用 `trim()`。`request_id` 可作为额外 correlation 字段或响应 header，但不能替代 `protocol_version/conversation_id/turn_id/sequence`，也不能成为另一套事件身份。

稳定事件名：

| 事件 | 首次出现 | 关键 payload |
|---|---|---|
| `chat.started` | current-release C1 | ChatEventBase、`created`；Conversation + USER 已 commit |
| `context.warning` | current-release C1 | ChatEventBase、component/code/message/retryable |
| `token.delta` | current-release C1 | ChatEventBase、`delta` |
| `post_turn.warning` | current-release C1 | ChatEventBase、component/code/message/retryable |
| `chat.completed` | current-release C1 | ChatEventBase、assistant_message_id/warning_count |
| `chat.failed` | current-release C1 | ChatEventBase、phase/error/partial_output_persisted |
| `tool.started` | S4 | ChatEventBase、tool name、call id、参数摘要 |
| `tool.completed` | S4 | ChatEventBase、call id、状态、citation ids |
| `citation.added` | S4 | ChatEventBase、Citation |
| `run.started` | S6 | ChatEventBase、run id、status |
| `run.status` | S6 | ChatEventBase、run id、新状态和原因 |
| `approval.required` | S8 | ChatEventBase、run/approval id、动作摘要、双期限 |
| `artifact.created` | S7 | ChatEventBase、run/artifact id、kind、version |
| `run.completed` | S6 | ChatEventBase、run id、result、usage、artifact ids |
| `run.failed` | S6 | ChatEventBase、run id、可重试性、错误码 |

S6 只是把同一 `sequence` 持久化为每 Run 单调递增的 RunEvent，并增加 `run_id`；它不删除 `conversation_id`，也不重命名 C1–S5 事件。客户端使用 `Last-Event-ID` 重连时先回放，再订阅实时流。

## 5. 状态机

```text
PENDING → RUNNING
RUNNING → WAITING_APPROVAL | COMPLETED | FAILED | CANCELLED
WAITING_APPROVAL → RUNNING | REJECTED | EXPIRED | CANCELLED
FAILED → PENDING（仅显式重试且错误可重试）
```

终态：`COMPLETED / FAILED / CANCELLED / REJECTED / EXPIRED`。

禁止：

- 从终态自动恢复；
- 批准后重新让模型生成一套不同的写参数；
- 取消后继续执行工具；
- 用 HTTP 连接是否断开判断 Run 是否结束。

## 6. 审批契约

```python
class ApprovalRequest(BaseModel):
    approval_id: UUID
    run_id: UUID
    step_id: UUID
    manifest_version: str
    manifest_jcs: bytes
    manifest_hash: str
    summary: str
    decision_expires_at: datetime
    execution_deadline: datetime
```

S8 的精确副作用必须先形成不可变 `ActionManifest`。`manifest_jcs` 是按 RFC 8785/JCS 规范化后的 UTF-8 bytes，`manifest_hash = SHA-256(manifest_jcs)`；JSONB 副本只供查询，不能参与授权比较。Manifest 至少绑定 tool/version、Project/Repository scope、source/target ref、expected base commit、Artifact/TestReport hash、sandbox image/profile/argv/harness 和双期限。完整字段以 S8 阶段卡为准，本公共类型不得退化回分散的可变参数。

批准时再次校验：

- run 仍处于 `WAITING_APPROVAL`；
- actor 等于服务端 sentinel，且本地静态策略允许对应 scope；
- 保存的 JCS bytes 复算后仍等于 `manifest_hash`，且 ActionManifest 绑定的 tool/scope/ref/commit/Artifact/验证证据未变化；
- `decision_expires_at` 尚未到；执行动作时 `execution_deadline` 也尚未到，批准不得延长期限；
- 相同 approval 尚未消费。

审批只恢复原 Step，不重新规划写操作。

## 7. 模型策略

### current-release C1–C3 与默认 S1/S2

- 保持现有 DeepSeek Chat 行为；
- 结构化输出继续使用当前 Pydantic 路径。

### S4 首次工具调用

- 使用 C3 冻结后重新 live 验证为支持标准 tool calling 的 DeepSeek 模型，并固定 **non-thinking**：

```python
extra_body={"thinking": {"type": "disabled"}}
```

- 首版不依赖 beta `strict` endpoint；
- 个人默认值为最多 3 个模型回合/4 次工具调用，服务端硬上限不高于 4/6；
- 达上限后生成受限总结或返回 `BUDGET_EXCEEDED`，不能无限循环。

选择 non-thinking 的原因是先缩小工具循环状态面。Thinking tool calls 要求完整回传
`reasoning_content`；默认路线不启用，未来只有独立评测和新路线授权后才可增加。

参考：

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)
- [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

## 8. API 演进

### 唯一 base path、scope 和 envelope

- C3 冻结的 Python HTTP base path `/api` 继续作为默认路线唯一 base path；不得只给部分新端点引入 `/api/v1`。
- 所有项目级 HTTP 请求只从 `X-Project-ID` 取得 Project scope；JSON body、query、cookie 和 Tool 参数不得出现第二个可独立生效的 `project_id`。
- `Idempotency-Key` 只来自 header。
- 除 SSE 外，所有 JSON endpoint 复用 C3 OpenAPI 冻结的统一 `Result[T]` envelope。示例必须使用 `{"code":1,"msg":"success","data":...}`；错误使用真实 HTTP status，并在同一 envelope 中返回稳定 `error_code`。
- Project list/create 等“选择 scope 本身”的端点不要求 `X-Project-ID`，但仍只允许本机访问。

### current-release C1–C3 至未来 S5

保留现有：

- `POST /api/chat/send`
- `POST /api/chat/send/stream`
- Conversation 查询和删除接口

请求可增加兼容字段 `mode=chat|agent`，默认 `chat`。

### 条件型 S6 起（默认路线不存在）

新增：

- `POST /api/agent-runs`
- `GET /api/agent-runs/{run_id}`
- `GET /api/agent-runs/{run_id}/events`
- `POST /api/agent-runs/{run_id}/cancel`
- `POST /api/agent-runs/{run_id}/retry`

### 条件型 S8 起（默认路线不存在）

新增：

- `GET /api/approvals/{approval_id}`
- `POST /api/approvals/{approval_id}/approve`
- `POST /api/approvals/{approval_id}/reject`

默认路线永久保留现有 Chat API。未来若触发 durable/action 路线，必须在新阶段卡中定义兼容
和删除条件，不能用旧编号自动淘汰同步 Chat。

## 9. 幂等与事务规则

以下 `run_id`/ToolCall 规则只在条件型 durable 路线启用。个人默认 S4/S5 不持久化 Run，
但必须复用 C1 TurnCoordinator，保证 USER/ASSISTANT/Citation 不重复写入。

- `save_message`：`run_id + role + logical_turn` 唯一。S6 必须在 Message 上落下可执行的 nullable `agent_run_id`/`logical_turn` 字段和 partial unique constraint（非 Agent 消息不受影响），不能只把它写成 service 层约定。冲突时必须核对 project、conversation、content/citation hash；不一致返回 `IDEMPOTENCY_MISMATCH`，不得覆盖旧消息。
- `ToolCall`：`run_id + logical_step_key + logical_tool_call_id` 唯一；`logical_step_key` 与 `logical_tool_call_id` 跨 Worker attempt/checkpoint 恢复保持稳定，attempt 单独记录，不能进入逻辑唯一键。
- 首次准备调用、尚未执行 Tool 前就持久化 logical keys。重复投递同一 logical key 且 canonical request hash 相同时复用已保存结果；同 key 但 request hash 不同返回 `IDEMPOTENCY_MISMATCH`，绝不覆盖或再次执行。
- 参数 hash 不能充当 logical ID：同一步以相同参数有意调用同一 Tool 两次时必须产生两个不同 logical IDs；同一逻辑调用重试时必须复用原 logical ID。
- `Artifact`：`run_id + kind + version` 唯一。
- `Approval`：一个 approval 只能消费一次。
- Redis 只做缓存、实时通知和队列 broker，不是真相源。
- Worker 每次执行自己创建 session；不得复用 FastAPI 请求级 `AsyncSession`。
- checkpoint 成功不代表领域事务成功；每个副作用节点必须可重入或显式去重。

## 10. 统一错误码

至少包括：

- `INVALID_REQUEST`
- `PROJECT_NOT_FOUND`
- `PROJECT_SCOPE_MISMATCH`
- `IDEMPOTENCY_MISMATCH`
- `FEATURE_DISABLED`
- `TOOL_NOT_ALLOWED`
- `TOOL_TIMEOUT`
- `TOOL_OUTPUT_TOO_LARGE`
- `MODEL_TIMEOUT`
- `BUDGET_EXCEEDED`
- `RUN_CANCELLED`
- `CHECKPOINT_CONFLICT`
- `APPROVAL_REQUIRED`
- `APPROVAL_EXPIRED`
- `ACTION_EXECUTION_EXPIRED`
- `APPROVAL_MISMATCH`
- `STALE_BASE_COMMIT`
- `PATCH_APPLY_FAILED`
- `SANDBOX_FAILED`

错误响应和事件不得暴露 API key、数据库 URL、完整系统 Prompt 或宿主绝对路径。

## 11. 可观测与评测

每个 Run/Chat 至少记录：

- request/run/conversation/project ID；
- runtime、model、Prompt、toolset、index 版本；
- 模型回合、工具次数、token/成本、总耗时；
- 检索和工具错误；
- citation 数量与用户反馈；
- 最终状态。

个人默认 S4/S5 使用结构化日志记录模型回合、工具、耗时、usage、Citation 数和错误，不要求
Graph node trace 或 Phoenix。只有可选 durable/observability 路线另行获批后才增加 OTel。
Prompt、源码、工具参数默认脱敏或采样，不把密钥和完整敏感内容写入 trace。

## 12. 兼容与删除计划

- 默认 S4 直接运行在 S2 service runtime，不存在 `service|graph` 双路径。
- 默认同步 Agent 路径在 S5 后继续保留；只有真实 durable 需求触发新路线时才评估迁移。
- feature flag 必须写明保留理由或触发式删除条件，不能依赖未选择的阶段编号。
- Java 版不新增 Agent 能力，只作 legacy 对照。
