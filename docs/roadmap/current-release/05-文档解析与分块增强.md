# C5：文档解析与分块增强

> 本阶段位于 C4 BM25 检索增强之后、任何 Agent 实施之前。目标是在不改变 Knowledge/Chat
> 对外契约、不引入 OCR/视觉模型的前提下，兑现 unstructured“元素感知分块”的原始设计意图：
> 让 DOCX/HTML/PDF 的标题与列表结构穿到分块层，PDF 文字版升级为布局启发式元素，扫描版
> 显式拒绝。
>
> **当前状态：已完成。** C5 实现元素感知序列化（Title->`#`、ListItem->`-`，DOCX/HTML 标题
> 穿到分块层）+ PDF pdfminer 字号标题检测 + 扫描版显式拒绝（`KNOWLEDGE_PDF_NO_TEXT_LAYER`）。
> before/after 评测：DOCX 两节文档旧链路 1 块（平铺）vs 新链路 2 块（标题边界，两节分离）。
> 42 测试 1.00s 通过。C5 不改 chunker 接口与参数、不碰 Memory 分块、不改前端/OpenAPI、
> 不修改共享 `golden_retrieval.py`。**C5 不产出 evidence manifest**（个人项目降密度：C1-C4 已有
> manifest 门禁，C5 改为测试 + before/after 评测报告作为完成标志，不走 validator 校验）。

## 1. 为什么单独设为 C5

C1-C 选 unstructured 就是为了元素感知分块，但实际链路只在解析端用了它一半：
`partition()` 拿到 Title/ListItem 元素后用 `str(e.text)` 压成纯文本、丢弃类型，
`SemanticChunker` 再对纯文本重新 `partition_md`。对真实 Markdown 标题能穿过去；对
DOCX/HTML/PDF 全部丢失，退化为 500 字定长滑窗。

C5 只补全这条链路（元素类型感知序列化 + PDF fast 分区 + 扫描版显式拒绝），不重做已经
闭环的父子表、Embedding、RRF、Query Rewrite、Chat Prompt 或 SSE，也不改 `chunk_by_title`
的切分参数。

## 3. 技术选择门禁

### 3.1 不得混淆的边界

| 项 | C5 决策 |
|---|---|
| 元素感知方式 | str 契约 + 类型感知序列化（Title->`#`、ListItem->`-`）；不改为元素直通 |
| PDF 解析 | `strategy="fast"`（pdfminer 布局启发式元素）+ pypdf 文本层探针 |
| 扫描版 PDF | 显式拒绝（`KNOWLEDGE_PDF_NO_TEXT_LAYER`），不引 OCR |
| 视觉模型 | 禁止 `unstructured[pdf]` / hi_res / unstructured-inference / google-cloud-vision |
| 标题前缀 | 只给 `Title` 元素加 `#`；不从普通段落“发明”标题 |

### 3.2 依赖最小子集

不安装 `unstructured[pdf]`（带入视觉模型，违反约束）。仅 pin：`pdfminer-six`、`pi-heif`、
`pdf2image`（过 importable 检查，fast 不调用）、`pillow`。fast 路径不需要系统 poppler。

### 3.3 残余风险（写入 ADR-0008）

- `#` 转义误判：与“用户直接上传 md”现状同构，不引入新错误类别。
- 标题层级扁平化：`chunk_by_title` 切分只依赖边界，不依赖层级，不影响正确性。
- PDF 长标题（>12 词）漏切：unstructured 文本块启发式局限，需 hi_res 才能改善（超边界）。

## 5. 测试计划

- `tests/test_document_parser.py`（现有断言零改动）：序列化断言（md `startswith("# ")`、
  DOCX `# heading`、List Bullet `- bullet`）；文本层 PDF fixture（pypdf 内容流注入，断言
  `# Section` 出现，对元素合并鲁棒）；集成断言（parse 喂 chunker -> chunk 数 ≥2，证明标题
  真实生效）；blank PDF 仍返回 `""`。
- `tests/test_knowledge_upload.py`（monkeypatch 契约零改动）：空白 PDF -> 400
  `KNOWLEDGE_PDF_NO_TEXT_LAYER` 且 0 行；文本层 PDF -> 200 且 chunk_count>0；`broken.md`
  空解析仍 `FILE_PARSE_FAILED`。
- `tests/eval/test_c5_chunking_quality.py`（新，自包含 before/after）：自有 DOCX+PDF fixture
  + 8-10 cases，同一文档两种分块方式（旧平铺滑窗 vs 新元素按标题切）各跑一遍，门禁
  R@5 无回归（>=），报告 MRR delta。**不修改共享 `golden_retrieval.py`**。
- 安全全量：`run_tests_safe.py -q` + `--cov` + 前端 `test/lint/build` 回归。

serializer + PDF 分支。
