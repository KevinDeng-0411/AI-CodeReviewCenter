# C3：当前版本冻结与交接

> 本阶段不增加产品能力。它把 C1/C2 已验证的行为、启动方式、文档和基线 commit 固定下来，防止后续 Agent 规划建立在失真的 README 或不可复现环境上。

## 1. 阶段结果

完成后，一个没有参与开发的人或另一个模型能够仅按文档：

```text
从空环境启动
→ 执行迁移
→ 运行自动测试
→ 打开前端
→ 复现 7 域演示
→ 查看当前限制
→ 安全回到冻结 commit
```

C3 完成只代表“当前 Chat 版本交付”。是否、何时进入 Agent 路线仍由用户另行决定。

## 2. 开工门槛

- `evidence/C1/manifest.json` 与 `evidence/C2/manifest.json` 均存在，且 `(cd codeaware-py && uv run python scripts/validate_stage_evidence.py C1)`、`(cd codeaware-py && uv run python scripts/validate_stage_evidence.py C2)` 分别通过。
- C2 后端、前端、browser E2E 和一次 live smoke 通过。
- C1 的 `run_tests_safe.py` 仍对开发/未知 PG、Redis、固定共享库和伪造 stack identity fail closed。
- 当前没有被文档掩盖的红测、临时 skip 或未解释 warning。
- 用户工作区的无关修改已识别，冻结过程不得覆盖。

## 4. 契约与配置冻结

### OpenAPI

生成规范化快照，例如：

```text
docs/api/openapi-current.json
```

CI 比较关键 contract；若 endpoint/schema 变化，必须显式更新快照和说明。快照不是替代 Pydantic，而是审查差异。

### 配置

`.env.example` 必须：

- 包含所有必要配置和安全默认值；
- 不含真实 key；
- 与 `Settings` 字段逐项测试；
- 标出 local-only 设置、大小/预算限制和可选 live 配置。

### 版本

在下列位置使用同一当前版本号：

- `pyproject.toml`
- FastAPI `version`
- 前端 package（若产品决定同步）
- evidence/release notes

具体版本号由实施时的发布约定决定，不由模型擅自创建 Git tag。commit/tag/push 仍需用户授权。

## 5. 空环境复现

提供非破坏性的 `codeaware-py/scripts/verify_current_release.sh`。它从仓库根调用，内部必须使用 `run_tests_safe.py` 创建/验证一次性 PG/Redis，不删除用户现有 volume。

它至少执行：

```text
依赖 lock 检查
→ 隔离 PostgreSQL/Redis 启动
→ Alembic 从零到 head
→ seed/constraint 验证
→ 后端全部普通测试
→ 前端 install lock/lint/test/build
→ API mocked E2E
→ 七域 browser E2E
→ 打印版本、commit 和结果摘要
```

调用方式固定为：

```bash
repo_root="$(git rev-parse --show-toplevel)"
cd "$repo_root"
./codeaware-py/scripts/verify_current_release.sh
```

脚本失败返回非零；不能吞掉某个子命令失败继续打印 PASS。它必须打印脱敏 stack identity、每个子命令退出码和精确清理结果，并证明开发 PG/Redis/volume 未变化。browser E2E 是 C3 必需项，不得通过选项静默跳过。

## 6. 基线指标

记录未来重构可对比的当前值：

| 指标 | 采集方式 |
|---|---|
| 后端测试数/跳过数/覆盖率 | pytest/coverage |
| 前端 lint/test/build | npm scripts |
| fresh bootstrap 时间 | verify script |
| Chat 首 token/P50/P95 | 固定 fake + 可选 live 样本 |
| Chat 完整响应耗时 | 同上 |
| RAG Recall@k 小型 golden set | 固定查询/相关 chunk |
| SSE 内容保真率 | 逐字符比较，目标 100% |
| 7 域 mocked E2E 成功率 | 固定任务集，目标 100% |
| live smoke 模型/日期/耗时/成本 | evidence，脱敏 |

当前数据量不足时可以标“基线样本小”，但不能留空后宣称已建立评测基线。

## 7. 安全与数据检查

- `git grep`/secret scanner 确认无真实 API key、token、`.env` 入库。
- AIReadMe path traversal/symlink 测试仍通过。
- 上传大小、类型和解析错误仍受限。
- 日志、错误、evidence 和 OpenAPI 不含宿主敏感绝对路径或连接串。
- destructive 测试和演示只作用于经 `run_tests_safe.py` 校验的本次一次性 PG/Redis；数据前缀不构成安全隔离。
- 数据备份/恢复、Alembic upgrade/downgrade 至少在一次性数据库演练一次；不得对开发、个人或生产库执行回退取证。

当前版本仍是 local-first、非多租户系统，必须在已知限制中明确，不能用 C1 的路径 allowlist 冒充完整 RBAC。

## 8. 可复制演示

由一名“未参与 C1/C2 的执行者”或新的模型按文档从仓库根运行：

```bash
repo_root="$(git rev-parse --show-toplevel)"
cd "$repo_root"
./codeaware-py/scripts/verify_current_release.sh
./codeaware-py/scripts/demo_c2_mocked.sh
```

`verify_current_release.sh` 已包含七域 browser E2E，不能再以“核心路径”替代。C3 必须验证 C2 `manifest.json` 已引用一次成功的 live smoke；若当前仍有凭据，可从仓库根重新运行 `./codeaware-py/scripts/demo_c2_live.sh`，但“本次未重跑”不能抹掉或伪造 C2 必需证据。

最后在 detached 临时 worktree + 另一套一次性 PG/Redis 中选择一个冻结前 commit/配置开关验证回退；不得切换用户当前 worktree。

交接人只能从 README 获取命令，不接受口头补充的隐含步骤。任何需要“先手动建一个库但文档没写”的情况都算失败。

- 已完成能力；
- C1 修复项；
- API/事件/配置兼容变化；
- 数据 migration；
- 已知限制；

- 下一步建议先评审项目隔离，不自动开始实施。

## 11. Agent 路线解锁条件

C3 `report.md` 与 `manifest.json` 必须遵循[阶段证据清单与解锁规则](../证据清单与解锁规则.md)。报告最后一节由交接者填写：

```text
当前版本是否完成：是 / 否
是否允许“评审” Agent 路线：是 / 否
是否授权“实施” Agent 第一阶段：否（除非用户另行明确授权）
```

即使前两项为“是”，默认也只是 `REVIEW_UNLOCKED`，允许评审[未来路线](../chat-to-agent/README.md)。后续模型不能把“路线已写好”解释为“已授权改造”；实施 S1 仍需用户在 C3 manifest 验证通过后另行明确授权。

## 12. 回退

- 冻结前记录精确 commit 和 Alembic head。
- 文档、应用和 migration 必须作为同一版本回退，不能只回代码不回契约。
- Git 回退演练只允许在 `mktemp -d` 创建、路径经校验、由目标 commit 建立的 detached 临时 `git worktree` 中进行；禁止在用户当前 worktree 执行 `checkout/reset/clean`。
- 临时 worktree 使用独立的一次性 PG/Redis stack；数据库 downgrade、备份和恢复演练只命中该 stack。对真实数据只编写备份、恢复和前向修复方案，不为 evidence 自动 downgrade。
- 回退验证前后记录用户 worktree 的 `git status` 和开发数据指纹，必须证明均未变化；记录临时 commit、脱敏 stack identity、退出码和精确清理结果。
- worktree、数据库、容器、网络或 volume 任一清理失败，rollback check 与 C3 均失败。
- 不自动创建/删除 tag、branch 或 remote release。
