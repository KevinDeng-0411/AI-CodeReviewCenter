# C1 手动可视化联调

> 本清单由项目所有者在真实开发栈上手动执行，属于 C1 自动 Evidence 之后的补充验证。
> 它不替代 `run_tests_safe.py`，也不阻塞机器 manifest。不要把 API key、宿主绝对路径、
> 完整连接串、真实敏感源码或未脱敏截图提交到仓库。

## 1. 准备

在 `codeaware-py/.env` 中配置有效 `LLM_API_KEY`。AIReadMe 只允许读取专用、无敏感
内容的 fixture；显式配置：

```dotenv
AI_README_SNAPSHOT_ENABLED=true
LOCAL_PROJECT_ROOTS=["<absolute-path-to-safe-fixture-parent>"]
```

从仓库根启动真实开发中间件和迁移：

```bash
docker compose up -d
./codeaware-py/scripts/ensure_python_db.sh
docker compose exec ollama ollama pull bge-m3
(cd codeaware-py && uv run alembic upgrade head)
```

使用两个终端分别启动后端与前端：

```bash
(cd codeaware-py && uv run uvicorn app.main:app --host 127.0.0.1 --port 8000)
(cd codeaware-py/frontend && npm run dev)
```

打开：

- 前端：<http://localhost:5173>
- OpenAPI：<http://localhost:8000/docs>
- 存活：<http://localhost:8000/health/live>
- 就绪：<http://localhost:8000/health/ready>
- AI 连通性：<http://localhost:8000/api/ai/health>

预期 AI 连通性中的 `llm/embedding/pgvector` 为 `true`，`dim=1024`。记录结果时只写
布尔值和维度，不复制失败异常或连接信息。

## 2. C1 关键链路

所有手工数据使用 `manual-c1-<YYYYMMDD>` 前缀。

| 链路 | 操作 | 通过标准 |
|---|---|---|
| Chat/SSE | 新建会话，要求返回 Markdown、代码块和多行文本 | 流式显示正常；空格、换行、代码块不粘连 |
| Chat 持久化 | 刷新页面并继续同一会话 | cid 不变；历史仍存在；新回答继续追加 |
| Summary | 连续完成五轮对话，再查看会话列表/API | summary 已出现；继续提问成功 |
| Knowledge | 上传无敏感内容的 Markdown，再搜索其中唯一关键词 | 上传成功；搜索结果包含该文档内容 |
| AIReadMe | 对专用 fixture 连续生成两次 | version 递增；hash 相同；文件数、时间、截断状态可见 |
| AIReadMe 拒绝 | 输入 allowed root 外路径 | 返回稳定业务错误，不展示宿主路径 |
| Readiness | 访问 live/ready | 正常状态均为 HTTP 200 |

真实模型输出不做逐字断言，只验证传输、结构、持久化和错误展示。

### 可选 Redis 降级

该步骤会短暂停止开发 Redis，但不应影响 PostgreSQL 真相：

```bash
docker compose stop redis
docker compose start redis
```

停止期间预期 `/health/live=200`、`/health/ready=503`；Chat 应完成或显示非阻塞 warning。
恢复后 `/health/ready=200`，刷新页面仍能看到已提交的 Chat 历史。确认 Redis 已恢复后再结束。

## 3. 手动记录

```text
日期：
commit：
浏览器：
LLM：pass / fail
Embedding 1024：pass / fail
PostgreSQL/pgvector：pass / fail
Chat/SSE：pass / fail
Summary：pass / fail
Knowledge multipart + search：pass / fail
AIReadMe version/hash/reject：pass / fail
Redis 降级（可选）：pass / fail / not-run
脱敏问题描述：
用户结论：
```

本记录默认保存在个人笔记中，不进入 C1 manifest 哈希链。若发现真实缺陷，记录问题并
修复；重新运行受影响定向测试、安全全量测试，并生成带
`supersedes_manifest_sha256` 的新 C1 Evidence。

## 4. 收尾

- 确保 Redis 已恢复。
- 用 `Ctrl+C` 停止前端和后端进程。
- 不执行 `docker compose down -v`。
- 将 AIReadMe snapshot 配置恢复为期望状态。
- 需要时通过 UI/API 删除 `manual-c1-<YYYYMMDD>` 数据。
