# CodeAware 0.1.0

发布日期：2026-07-30

状态：C3 当前版本冻结候选；最终 validated commit 与证据以
[C3 manifest](../roadmap/current-release/evidence/C3/manifest.json)为准。

## 本版本完成

- 以 FastAPI + React 作为当前实现，Java 模块仅保留为迁移参考。
- Chat 提供同步与 typed SSE、多轮持久化、短期窗口、增量摘要、长期记忆和 Knowledge
  RAG 上下文。
- Code Review、Unit Test、AIReadMe、Prompt、Knowledge、Memory 七个已有功能域完成
  API、数据库、错误分支和 UI 闭环。
- OpenAPI、环境变量、前后端版本号、安全测试入口和可重复演示被冻结。

## C1 修复

- SSE 使用带 `protocol_version/conversation_id/turn_id/sequence` 的类型化事件；token 的
  空格和换行逐字符保真。
- USER/ASSISTANT、摘要和缓存写入以 PostgreSQL 为真相源；Redis 故障可观测降级。
- 摘要按水位线增量处理，条件更新避免并发覆盖。
- Knowledge 文件上传采用受限 multipart 解析，AIReadMe 仅扫描 allowed root 内的有界
  只读快照。
- fresh volume 双数据库、liveness/readiness、安全测试 sentinel 和精确资源清理通过。

## 契约与兼容变化

- 会话标识统一为 `conversation_id`，不提供 `session_id`。
- 流式响应不再使用裸 token 或 `[DONE]`；终态为 `chat.completed` 或 `chat.failed`。
- 当前 OpenAPI 为 27 个 paths、29 个 operations，以
  [`codeaware-py/openapi/current-release.json`](../../codeaware-py/openapi/current-release.json)
  为唯一快照。
- `.env.example` 与 Pydantic `Settings` 字段逐项一致；AIReadMe snapshot 默认关闭。
- Knowledge 词法腿仍是 `pg_trgm similarity`，不是 BM25。

## 数据迁移

- Alembic 唯一 head 为 `0005`。
- `0001` 建立 8 表目标模型；`0002` seed 四类 Prompt；`0003` 增加摘要水位线；
  `0004` 增加 AIReadMe snapshot 元数据和版本唯一约束；`0005` 收紧 Prompt
  type/version 与长期记忆类型约束。
- 应用、OpenAPI 与 migration 应作为一个版本整体回退，不能只回退其中一部分。

## 已知限制

- local-first、单用户；没有认证、RBAC 或多租户隔离。
- per-conversation turn guard 位于单进程内，只支持单 worker；多 worker 前必须改为
  PostgreSQL 条件 lease。
- Unit Test 只生成与保存源码，不执行生成代码。
- 普通测试使用 fake LLM/embedder；真实 DeepSeek/Ollama 只由显式 live smoke 验证。
- 前端生产 bundle 仍有体积优化空间。
- 尚无 Agent Tool loop、Citation、仓库索引、shell、patch、Git 写入或多 Agent。

## 验证与回退

完整冻结验证：

```bash
./codeaware-py/scripts/verify_current_release.sh
```

回退演练只在 detached 临时 worktree 和一次性 PG/Redis 中运行，包含 `0005` 迁移往返与
逻辑备份/恢复：

```bash
./codeaware-py/scripts/verify_c3_rollback.sh
```

真实数据回退前必须先独立备份并验证恢复；禁止为了演示对开发或生产数据库执行
`alembic downgrade`。优先采用前向修复；确需 Git 回退时选择 C3 manifest 记录的
validated commit，并同步使用该 commit 的 OpenAPI、配置与 migration。
